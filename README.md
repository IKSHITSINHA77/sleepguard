# SleepGuard — Sleep Disorder Classification

SleepGuard is an educational machine-learning application that explores classification of sleep-disorder patterns from sleep and lifestyle attributes. It includes a Flask web interface, validated prediction API, model comparison, and saved evaluation visualisations.

> **Important:** SleepGuard is a student/research project, not a medical device. Predictions are not diagnoses, calibrated clinical risk scores, or medical advice. Consult a qualified healthcare professional about sleep or health concerns.

## Current features

- User registration, sign-in, and sign-out with a SQLite user database.
- Passwords stored using Werkzeug's secure password-hashing utilities; authenticated sessions protect the dashboard, prediction, analytics, and report routes.
- CSRF checks on account forms, sign-out, and prediction requests.

- Flask web application with Overview, Assessment, Model Analytics, and About sections.
- Validated assessment form for personal, sleep, lifestyle, and health indicators.
- Three-class model output: `None`, `Insomnia`, or `Sleep Apnea` (depending on labels present in the training data).
- Class probability estimates from the trained classifier. These are model probabilities, not clinically calibrated risks.
- Six classifiers: SVM, KNN, Decision Tree, Random Forest, ANN-MLP, and soft-voting ensemble.
- Repeated stratified cross-validation; model selection by macro F1.
- Hold-out evaluation, classification report, confusion matrix, and permutation feature importance.
- Analytics page reads the saved training reports; it does not fabricate metrics.

## Dataset and training

### Use the real Kaggle dataset

Download the Sleep Health and Lifestyle Dataset from:
https://www.kaggle.com/datasets/uom190346a/sleep-health-and-lifestyle-dataset

Place the CSV at:

`data\Sleep_health_and_lifestyle_dataset.csv`

Then run:

```powershell
python -m src.train
```

### Synthetic data (software smoke test only)

The repository includes `data\synthetic_sleep.csv`. It is generated sample data, not the original Kaggle dataset and not suitable for claiming real-world model performance. To train a local demonstration model with it:

```powershell
python -m src.train --data data/synthetic_sleep.csv
```

The default configuration expects the original Kaggle CSV. If you train using the synthetic file, the resulting model and metrics will reflect synthetic patterns only.

Training writes:

- `models\model.joblib`
- `models\meta.json`
- `reports\cv_results.csv`
- `reports\classification_report.txt`
- `reports\confusion_matrix.png`
- `reports\feature_importance.png`

## User accounts

On first run, open `http://127.0.0.1:5000/register` and create a user account. After registration, SleepGuard signs the user in and opens the dashboard. Returning users can use `/login`. User accounts are stored locally in `sleepguard_users.db`; passwords are stored as hashes, not plain text. The database file is created automatically and should be backed up if you need to preserve local accounts.

For a persistent secret key, set an environment variable before starting the app (PowerShell):

```powershell
$env:SLEEPGUARD_SECRET_KEY = "replace-this-with-a-long-random-secret"
```

For a public HTTPS deployment, also set `$env:SLEEPGUARD_HTTPS = "1"`, use HTTPS, and configure a production WSGI server. The built-in Flask development server is for local development only. The default generated secret key changes on each restart unless `SLEEPGUARD_SECRET_KEY` is set, which will invalidate existing sessions after a restart.

## API

`POST /api/predict` accepts JSON with these fields:

- Numeric: `Age`, `Sleep Duration`, `Quality of Sleep`, `Physical Activity Level`, `Stress Level`, `Heart Rate`, `Daily Steps`, `Systolic`, `Diastolic`
- Categorical: `Gender`, `Occupation`, `BMI Category`

Example:

```json
{
  "Gender": "Male",
  "Age": 40,
  "Occupation": "Nurse",
  "BMI Category": "Normal",
  "Sleep Duration": 6.5,
  "Quality of Sleep": 6,
  "Stress Level": 6,
  "Physical Activity Level": 45,
  "Daily Steps": 6000,
  "Heart Rate": 72,
  "Systolic": 130,
  "Diastolic": 85
}
```

Other endpoints:

- `GET /health` — application/model readiness.
- `GET /api/analytics` — saved model comparison and report locations.

## Methodology and limitations

Preprocessing is fitted inside each scikit-learn pipeline to reduce data leakage. Duplicate rows are removed before splitting by default. Model selection uses repeated stratified cross-validation on the training partition; the selected model is evaluated on a separate stratified hold-out partition. Macro precision, macro recall, macro F1, and accuracy are reported because class imbalance can make accuracy alone misleading.

The public dataset is relatively small and may contain repeated or under-representative records. Performance on this dataset does not establish clinical validity or generalisation to an individual. Synthetic data must be clearly labelled and must not be used to report meaningful clinical performance.
